# 法言法语润色技能

法律中文的表达工作台：**只处理表达、结构和一致性，不做法律判断。**

## 工作边界（先明确不做什么）

| 做 | 不做 |
|----|------|
| 修正语病、冗余、指代不明 | 替用户选择法律规范或诉讼策略 |
| 规范法律术语与称谓 | 改变实体结论或证明标准 |
| 调整句式与段落逻辑 | 补充材料里没有的事实 |
| 诊断结构、核对多份文书一致性 | 替代事实核查与法条核验（那是 `legal-research`、`legal-analysis-pitfalls` 的活） |

## 五条红线（违反即返工）

1. **不新增事实**：不添加当事人、时间、金额、条件、因果关系、请求或法律结论；
2. **不升级主张**：不把"我方认为""证据显示"改写成"已经认定""足以证明"；
3. **不改不确定性**：原文的"可能""或者""原则上"要保留，否定范围与规范强度不能动；
4. **不填补缺口**：材料缺事实、缺依据时，**不要用"完整结构"为理由补写**，标记出来交给用户；
5. **不静默改法条**：发现疑似实体法律错误（条号错、条文内容不符、引用已废止法规）只标"需核验"，不改，也不删。

## 处理动作

### 四种转换模式

| 动作 | 做什么 | 什么时候用 |
|------|--------|------------|
| **轻度润色** | 修语病、去冗余、明确指代和格式，不重构 | 文本已成熟，只差打磨 |
| **专业改写** | 规范术语、调整句式、重组段落逻辑 | **默认动作** |
| **严格审校** | 语义、结构、风险、引用、一致性全查 | 合同、诉讼材料、意见书、函件、高风险外发文本 |
| **通俗转译** | 向非法律读者解释必要术语，保持结论强度与例外 | 给当事人的说明、庭审汇报 |

### 两个专项动作

| 动作 | 产出 |
|------|------|
| **结构诊断** | 只报告问题：工作产品类型、受体、主命题、信息层级、对应关系、缺口；**不给改写稿**，除非用户同时要求 |
| **文书链核对** | 比对多份文本中的主体、角色、日期、金额、术语、请求、证据状态、立场、引用、结果；**不统一改写全部文件**，除非用户同时要求 |

## 工作流

### 第一步：判断输入

- **直接入口**：材料已给、任务明确 → 直接处理，不追加问卷；
- **引导入口**：用户第一次用、说不清要做什么 → 用不超过三个短问题确定动作与受体；
- **材料入口**：还没给文本 → 请用户提供，并提示按需脱敏。

结构诊断至少需要一份文本；文书链核对至少需要两份关联文本。

### 第二步：内部路由（不外显）

在心里确定四件事，**不要展示完整路由过程**：

1. **工作产品**：记录 / 请求 / 回应 / 分析建议 / 约定 / 决定 / 解释传播（见 `references/functions.md`）；
2. **沟通关系**：谁以什么身份写给谁（见 `references/audiences.md`）；
3. **处理动作**：上面四种模式或两个专项动作用哪一个；
4. **修正项**：是否涉及对抗性、面向法院、口头表达、敏感信息、现行规范变化。

按文本的主要功能选**一个**主类型；确有复合功能时最多再加一个辅助类型。**不要按部门法或文件名称机械分类**。

需要说明时只用一行：`处理建议：回应型 × 律师向法院 × 严格审校。`

### 第三步：只在必要时追问

只有出现下列高影响歧义时，才提**最多两个**问题并暂停：

- 关键行为主体或写作主体不明；
- 日期、金额、请求、事实相互冲突；
- 两种写法会改变法律效果或程序立场；
- 分不清某处模糊是刻意安排还是表达失误；
- 用户要求把未核实的事实写成确定结论。

能用保守表达继续处理的，不为次要偏好停下。

### 第四步：执行

按选定动作处理。**保留原有的编号、标题层级、引用格式和段落顺序**，除非用户明确要求重构。

### 第五步：双重复核（严格审校、结构诊断、文书链核对、长文本必做）

1. **校异同**：对照原文、附件、引文、关联文书，核对语义与数据是否被改动；
2. **校是非**：检查本稿内部的主体、术语、条件、逻辑、结构、表达是否自洽。

自检清单见 `references/checklist.md`。

### 第六步：交付

| 动作 | 交付内容 |
|------|----------|
| 轻度润色 / 专业改写 | `修改稿`；必要时加 `需确认事项` |
| 严格审校 | `修改稿` + `需确认事项` + `主要修改` |
| 通俗转译 | `修改稿`；必要时加 `术语说明` |
| 结构诊断 | `路由判断` + `结构诊断` + `信息缺口与风险` + `建议处理顺序` |
| 文书链核对 | `核对范围` + `一致事项` + `差异与风险` + `建议修正` |

用户同时要专项动作和改写时：**先报诊断或差异，再给修改稿**。

## 术语与称谓

近义法律术语、身份称谓、法律效果词的选择（"解除"与"撤销"、"定金"与"订金"、"应当"与"可以"），按下表处理：

- 原文用词正确但口语化 → 替换为规范表述；
- 原文用词错误（把"撤销"写成"解除"） → **不自行改**，标注"需核验：此处用词可能涉及法律效果，请确认"；
- 称谓前后不一致 → 统一，但保持与主体信息一致（见 `references/examples.md`）。
