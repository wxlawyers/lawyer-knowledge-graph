```bash
python3 scripts/sync_guardrails.py            # 同步
python3 scripts/sync_guardrails.py --check    # 只检查是否一致，不写入
```

## 事实核验原则

> 完整规则见 `../_shared/guardrails.md`（单一来源，勿在本文件单独修改此段）。核心不变：法条、案例、案号、金额与事实结论必须可回源到真实材料或实际检索结果，禁止编造或凭记忆补全；无法核验时输出 `[待补: ...]` 并说明去哪里查；交付前由使用者复核全部引用与数字。

## 展开说明（人读）

这三句是全部技能的底线要求，展开讲是下面几层意思。

### 1. 可回源

"可回源"指：任何写进产出的法条、案例、案号、金额、事实结论，都能指回一个真实来源——卷宗里的某一页、MCP 返回的某一条、当事人确认的某一句。

做不到，就要检查是不是在凭记忆补全。凭记忆写出来的法条条文、案号、裁判要旨，是最容易出错、也最伤专业信誉的一类错误。

### 2. 无法核验时怎么处理

不要硬写，也不要略过。标准做法是留占位符：

```
[待补: 缺什么，应该去哪里查]
```

例如 `[待补: 该省最新年度城镇居民人均可支配收入，需查省统计局公报]`。占位符对使用者是有用信息——他知道还差什么、去哪儿补，而不是以为这里已经查过了。

### 3. 交付前复核

AI 产出在对外使用前，必须由使用者核对全部引用与数字。**核验状态只有两种**：已核验（附来源与日期），或待核实（明确标注）。不得把未核验内容表述成已核验。

法条引用的具体核验流程，见 `legal-analysis-pitfalls` 技能的《法条引用核验协议》（`references/citation-verification-protocol.md`）：三层校验 + 阻断规则。

### 4. 与「阻断」的关系

本护栏只规定"必须可回源、必须标注、必须复核"。至于核验不通过时是否阻断交付、怎么标记，属于各技能自己的门禁设计（例如法条核验协议里的 `[阻断-法条核验: 原因]`）。
