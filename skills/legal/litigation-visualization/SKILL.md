# 诉讼可视化技能

把散落在判决书、合同、流水、聊天记录和证据目录里的事实，变成**一张能看懂的图**。

## 适用场景

| 图 | 解决什么问题 | 常用时机 |
|----|--------------|----------|
| **时间线图 / 大事记** | 事情按什么顺序发生、哪几个节点是关键 | 诉前评估、起诉与答辩的事实部分、庭前准备 |
| **法律关系图** | 谁与谁、就哪份合同或哪段事实、形成什么关系 | 主体复杂、多层转手、担保与关联交易 |
| **庭前对抗图** | 我方主张什么、法院要审什么、对方可能怎么应、哪一处是决定性的 | 庭前推演、向当事人汇报 |
| **证据图** | 每份证据连到哪个待证事实、哪里还是空的 | 举证前、质证准备 |

## 三条通用纪律（先记住，再看具体画法）

### 1. 照录原文，不替当事人改写

图上的事实来自材料原文。**不要润色、不要归纳成"综上"、不要把推测写进去。**

材料本身表述模糊的，照抄模糊表述，或在图上留空，不要自行挑一个说法填上。

### 2. 每张图挂出处

每个事件、每个关系、每份证据，都要能指回来源：材料名称 + 页码 / 案号 / 时间戳。

导出时附一份**出处索引表**。看图的人任何一处存疑，都能立刻回原件核对。

### 3. 先说清楚"给谁看"

同一份材料，内部推演图和对外图**不是一回事**：

| 用途 | 能画什么 | 红线 |
|------|----------|------|
| 内部推演 / 团队讨论 | 全部：争点、要件、策略判断、胜败评估 | —— |
| 给当事人 | 事实经过、程序进展、可选方案 | 不写策略底牌、不写对法官和对方的主观评价 |
| 可对外提交（法院、对方） | 只画客观事实与法律关系，且每处有出处 | **不画判断、不画策略、不画胜负预测** |

**庭前对抗图默认不外传**：它包含要件判断与抗辩预判，属于内部推演材料。需要向当事人展示时，另出一份删去策略部分的事实版。

## 判断类图要"带标"

时间线和法律关系图只照录，不做判断。对抗图与证据图必然包含判断，因此**每一条判断都要带标**：

| 标注 | 含义 |
|------|------|
| 法律层面置信 | 高 / 中 / 低——该认定在法律规定上的把握 |
| 证据层面置信 | 高 / 中 / 低——现有证据的支持程度 |
| 来源 | 依据哪份材料或哪条法律规定 |

**法律层面与证据层面分开评级**，不要合成一个分数。两栏分开，才能看出"法律上站得住但证据不足"和"证据充分但法律定性有争议"这两类完全不同的处境。

**结论留空**：证明前景、胜负判断、法院可能另作定性这类结论，只给方向，留给律师填。

## 输出形态

一次交付**三样**，不要只给一张图：

1. **图**：Mermaid 代码（Obsidian 里可直接渲染，可搜索、可版本管理）或 SVG；
2. **母表**：图背后的结构化数据（Markdown 表格或 JSON），方便改一处重出图；
3. **出处索引**：每条内容对应的材料与位置。

### 形式选择

| 形式 | 什么时候用 |
|------|------------|
| Mermaid | 默认。Obsidian 原生渲染，改文字就能改图，适合笔记与内部使用 |
| SVG / PNG | 需要打印、插入 Word、当庭展示时 |
| WPS 思维导图 | 庭审记录、要点梳理类（见 `trial-preparation` 步骤七） |

### 生成 SVG

时间线可以直接用脚本从结构化数据渲染：

```bash
python3 scripts/timeline_svg.py events.json -o 时间线.svg
```

数据格式与参数见脚本开头的说明。

## 克制原则

- **一张图讲一件事**。时间线不塞法律关系，关系图不塞争点，混在一起谁都看不懂；
- **颜色只用一个强调色**：标出最关键的一两处即可，全图都是重点等于没有重点；
- **模块数量控制住**：同一张图上并列的模块超过 9 个，先问用户要不要拆图，不要硬塞；
- **文字能省则省**：图上写不下的细节放到底稿表里，图上留短句。

## 交付说明（每张图都附）

```
图名：
用途：内部推演 / 给当事人 / 可对外提交
数据来源：材料清单（含是否有扫描件、是否靠读图提取）
未确认事项：列出待核实的内容
生成日期：
```

**特别注意**：如果材料是扫描件或照片、靠读图提取，必须在交付说明里**声明哪几条来自读图**，并提示回原件复核。

## 质量门禁

出图前后各检查一遍：

- [ ] 图上每一条都能指回出处（材料名 + 页码/案号/时间戳）
- [ ] 没有把推测、评价、"综上"写进事实层
- [ ] 时间顺序正确；同一天多个事件的排序规则已说明
- [ ] 金额、日期、名称与材料一致
- [ ] 判断类条目都带了三标（法律置信 / 证据置信 / 来源）
- [ ] 结论部分留空或有明确标注，没有替律师下判断
- [ ] 交付说明写明用途与出示范围
- [ ] 扫描件来源的条目已单独声明

## 常见错误

| 错误 | 后果 |
|------|------|
| 把内部推演图直接给当事人或对方 | 暴露策略底牌 |
| 事实层混入法律评价 | 看图的人分不清哪些是材料写的、哪些是律师推的 |
| 只交一张图，没有母表和出处 | 对方一处质疑，整张图都要重做 |
| 用颜色把什么都标成重点 | 视觉噪声，关键点反而被淹没 |
| 扫描件内容不声明来源 | 与原件不符时无法解释 |
| 缺材料的地方自行填补 | 一旦被核对出来，全案可信度受损 |

## 素材要求

材料怎么给都行：判决书、起诉状、答辩状、代理词、合同、证据目录、银行与支付流水、微信聊天记录、扫描件、手机照片，甚至一段口述。

不必先整理。但**口述与未核实的内容必须单独标记**，不能与有书面出处的内容混在一张图上。
